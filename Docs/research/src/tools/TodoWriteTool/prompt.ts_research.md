# prompt.ts 研究文档

## 场景与职责

`prompt.ts` 是 `TodoWriteTool` 的提示词定义文件，包含两个核心导出：
- `PROMPT` - 详细的工具使用说明，指导 AI 何时以及如何使用 TodoWrite 工具
- `DESCRIPTION` - 工具的一行描述，用于工具列表展示

该文件是 AI 行为控制的关键组成部分，通过精心设计的提示词引导 AI 在多步骤任务中主动使用任务列表功能。

## 功能点目的

### 1. 使用场景指导（When to Use）
明确告知 AI 应该使用 TodoWrite 的场景：
- 复杂多步骤任务（3+ 个不同步骤）
- 非平凡且复杂的任务
- 用户明确要求使用待办列表
- 用户提供多个任务
- 收到新指令后立即捕获
- 开始处理任务前标记为进行中
- 完成任务后更新状态

### 2. 禁用场景指导（When NOT to Use）
明确告知 AI 不应使用 TodoWrite 的场景：
- 单一、直接的任务
- 平凡的任务（跟踪无组织收益）
- 可在少于 3 个简单步骤内完成的任务
- 纯对话或信息性任务

### 3. 任务状态管理
定义三种任务状态：
- `pending` - 任务尚未开始
- `in_progress` - 当前正在处理（限制一次只有一个）
- `completed` - 任务成功完成

### 4. 任务描述格式规范
要求每个任务必须提供两种形式：
- `content` - 祈使句形式（如 "Run tests", "Build the project"）
- `activeForm` - 现在进行时形式（如 "Running tests", "Building the project"）

## 具体技术实现

### 提示词结构

```
PROMPT = 
├── 工具用途概述
├── 何时使用此工具（7 个场景）
├── 何时不使用此工具（4 个场景）
├── 使用示例（4 个正面示例 + reasoning）
├── 不使用示例（4 个负面示例 + reasoning）
└── 任务状态和管理规范
    ├── 任务状态定义
    ├── 任务管理规则
    ├── 任务完成要求
    └── 任务分解指南
```

### 示例设计模式

每个示例包含：
1. **场景描述** - 用户请求
2. **AI 行为** - 具体行动
3. **reasoning 块** - 解释为什么（不）使用工具

这种设计帮助 AI 学习模式识别和推理过程。

### 关键规则提取

| 规则类别 | 具体规则 |
|----------|----------|
| 状态唯一性 | 恰好一个任务必须是 `in_progress`（不能多不能少） |
| 实时更新 | 工作时实时更新任务状态 |
| 立即标记 | 完成任务后立即标记（不要批量） |
| 阻塞处理 | 遇到错误/阻塞时创建新任务描述解决方案 |
| 完成标准 | 测试通过、实现完整、无未解决错误 |
| 双形式要求 | 必须提供 content 和 activeForm |

## 风险、边界与改进建议

### 风险

1. **提示词注入风险**
   - 提示词中包含用户输入的插值（如 `${FILE_EDIT_TOOL_NAME}`）
   - 虽然当前是安全的常量引用，但模式本身需要注意

2. **V2 系统冲突**
   - 提示词描述的是 V1 行为
   - 当 V2 系统启用时，这些指导可能不再适用
   - 建议：添加版本说明或迁移提示

3. **语言限制**
   - 提示词完全使用英文
   - 非英语用户可能无法充分利用此功能
   - 建议：考虑国际化支持

4. **规则过于严格**
   - "恰好一个 in_progress" 规则在某些并行场景下可能不适用
   - 例如：等待外部反馈时是否可以开始其他任务？

### 边界情况

1. **任务数量边界**
   - 提示词建议 3+ 步骤使用工具
   - 但 2 个复杂步骤是否也应该使用？边界模糊

2. **任务粒度**
   - "搜索并替换 15 个文件" 算 1 步还是 15 步？
   - 提示词中的示例 2 表明应细化为每个文件一个任务

3. **错误处理**
   - 提示词提到遇到错误时创建新任务
   - 但未明确说明原始任务应如何处理（保持 in_progress？）

### 改进建议

1. **添加版本标识**
   ```typescript
   // @deprecated This prompt is for Todo V1. Task V2 uses different tools.
   export const PROMPT = `...`
   ```

2. **增强示例覆盖**
   - 添加并行任务处理示例
   - 添加错误恢复场景示例
   - 添加长时间运行任务（需要等待外部系统）示例

3. **明确任务粒度指导**
   ```
   ## Task Granularity Guidelines
   - 每个任务应该是可独立完成的单元
   - 如果任务涉及多个文件，考虑按文件分解
   - 如果任务有明确的检查点，考虑分解为子任务
   ```

4. **添加元数据支持说明**
   - 如果未来支持任务优先级、截止日期等，应在提示词中说明

5. **考虑提示词压缩**
   - 当前 184 行可能占用较多 token
   - 可考虑精简示例数量或使用更简洁的表达

6. **与 V2 提示词统一**
   - 如果 V1 和 V2 并存，确保两者的指导原则一致
   - 避免 AI 在不同模式下行为不一致
