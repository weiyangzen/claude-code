# ClaudeCodeInternalEvent 类型定义研究文档

## 1. 场景与职责

### 1.1 文件定位
`src/types/generated/events_mono/claude_code/v1/claude_code_internal_event.ts` 是 Claude Code CLI 内部事件日志系统的核心 Protocol Buffers 类型定义文件。该文件由 `protoc-gen-ts_proto` 自动生成，源文件为 `events_mono/claude_code/v1/claude_code_internal_event.proto`。

### 1.2 核心职责
该文件定义了 Claude Code CLI 向 Anthropic 内部数据分析系统（BigQuery）上报事件的标准数据结构，承担以下关键职责：

1. **事件标准化**：统一所有内部事件的数据格式，确保事件可被正确存储和分析
2. **PII 管控**：通过结构化字段分离敏感数据（如 skill_name、plugin_name、marketplace_name）到受控列
3. **环境追踪**：捕获运行时环境信息（平台、版本、CI 环境等）用于故障排查和使用分析
4. **多租户支持**：支持 Swarm/Team Agent 场景下的会话关联和代理识别

### 1.3 使用场景
- **1P 事件日志上报**：通过 `/api/event_logging/batch` 端点批量上报事件
- **GrowthBook 实验曝光追踪**：记录 A/B 测试实验分配结果
- **SWE-bench 评测**：支持软件工程基准测试的场景追踪
- **GitHub Actions 集成**：CI/CD 环境下的使用分析

## 2. 功能点目的

### 2.1 核心数据接口

#### 2.1.1 `ClaudeCodeInternalEvent`（主事件接口）
代表通过 Statsig 从 Claude Code 记录的事件，对应 BigQuery 表 `proj-product-data-nhme.raw_statsig_internal_tools.events`。

**关键字段分类**：

| 类别 | 字段 | 说明 |
|------|------|------|
| 基础标识 | `event_name`, `event_id`, `client_timestamp`, `server_timestamp` | 事件名称、唯一ID、时间戳 |
| 会话信息 | `session_id`, `parent_session_id`, `device_id` | 会话关联 |
| 模型信息 | `model`, `betas` | 使用的模型及beta特性 |
| 用户身份 | `email`, `user_type`, `auth` | 用户邮箱、类型、认证信息 |
| 环境元数据 | `env` (EnvironmentMetadata) | 运行时环境详情 |
| 进程指标 | `process` | 内存、CPU等进程指标（Base64编码JSON） |
| 扩展元数据 | `additional_metadata` | 事件特定的额外数据（Base64编码JSON） |
| SWE-bench | `swe_bench_*` | 评测任务标识 |
| Swarm/Agent | `agent_id`, `agent_type`, `team_name` | 多代理场景识别 |
| Slack 集成 | `slack` (SlackContext) | Claude-in-Slack 上下文 |
| PII 受控字段 | `skill_name`, `plugin_name`, `marketplace_name` | 特权列数据 |

#### 2.1.2 `EnvironmentMetadata`（环境元数据）
包含环境和运行时信息，与 `claude-cli-internal/src/services/statsig.ts` 中的字段定义保持一致。

**关键字段**：
- **平台信息**：`platform`, `platform_raw`, `arch`, `node_version`
- **运行时**：`terminal`, `package_managers`, `runtimes`, `is_running_with_bun`
- **CI/CD 环境**：`is_ci`, `is_github_action`, `is_claude_code_action`
- **GitHub Actions 专用**：`github_event_name`, `github_actions_runner_*`, `github_actions_metadata`
- **远程环境**：`is_claude_code_remote`, `remote_environment_type`, `claude_code_container_id`
- **部署信息**：`deployment_environment`, `version`, `version_base`, `build_time`
- **WSL/Linux**：`wsl_version`, `linux_distro_id`, `linux_distro_version`, `linux_kernel`
- **其他**：`is_claubbit`, `is_claude_ai_auth`, `is_local_agent_mode`, `is_conductor`, `vcs`

#### 2.1.3 `GitHubActionsMetadata`（GitHub Actions 专用元数据）
```typescript
export interface GitHubActionsMetadata {
  actor_id?: string
  repository_id?: string
  repository_owner_id?: string
}
```

#### 2.1.4 `SlackContext`（Claude-in-Slack 上下文）
包含每个 CIS 事件都有的上下文字段：
```typescript
export interface SlackContext {
  slack_team_id?: string
  is_enterprise_install?: boolean
  trigger?: string
  creation_method?: string
}
```

### 2.2 序列化/反序列化工具

每个接口都配有完整的 `MessageFns<T>` 实现：
- `fromJSON(object: any): T` - 从 JSON 解析
- `toJSON(message: T): unknown` - 序列化为 JSON
- `create<I extends Exact<DeepPartial<T>, I>>(base?: I): T` - 创建实例
- `fromPartial<I extends Exact<DeepPartial<T>, I>>(object: I): T` - 从部分对象创建

### 3.2 类型工具定义

#### 3.2.1 DeepPartial<T>
支持嵌套对象的深度部分类型：
```typescript
type DeepPartial<T> = T extends Builtin
  ? T
  : T extends globalThis.Array<infer U>
    ? globalThis.Array<DeepPartial<U>>
    : T extends ReadonlyArray<infer U>
      ? ReadonlyArray<DeepPartial<U>>
      : T extends {}
        ? { [K in keyof T]?: DeepPartial<T[K]> }
        : Partial<T>
```

#### 3.2.2 Exact<P, I>
确保输入类型严格匹配原型，防止额外字段：
```typescript
type Exact<P, I extends P> = P extends Builtin
  ? P
  : P & { [K in keyof P]: Exact<P[K], I[K]> } & {
      [K in Exclude<keyof I, KeysOfUnion<P>>]: never
    }
```

#### 3.2.3 时间戳处理
```typescript
function fromTimestamp(t: Timestamp): Date {
  let millis = (t.seconds || 0) * 1_000
  millis += (t.nanos || 0) / 1_000_000
  return new globalThis.Date(millis)
}

function fromJsonTimestamp(o: any): Date {
  if (o instanceof globalThis.Date) {
    return o
  } else if (typeof o === 'string') {
    return new globalThis.Date(o)
  } else {
    return fromTimestamp(Timestamp.fromJSON(o))
  }
}
```

### 3.3 默认值处理
每个接口都有对应的 `createBase*` 函数定义默认值：
- 字符串字段默认为 `''`
- 布尔字段默认为 `false`
- 数组字段默认为 `[]`
- 对象字段默认为 `undefined`

### 4.4 元数据转换关键代码

在 `metadata.ts` 的 `to1PEventFormat()` 函数中：

```typescript
// 关键注释说明：
// IMPORTANT: env is typed as the proto-generated EnvironmentMetadata so that
// adding a field here that the proto doesn't define is a compile error. The
// generated toJSON() serializer silently drops unknown keys — a hand-written
// parallel type previously let #11318, #13924, #19448, and coworker_type all
// ship fields that never reached BQ.
// Adding a field? Update the monorepo proto first (go/cc-logging):
//   event_schemas/.../claude_code/v1/claude_code_internal_event.proto
// then run `bun run generate:proto` here.
```

这明确说明了使用生成的 `EnvironmentMetadata` 类型而非手写类型的原因——编译时类型检查可以防止字段遗漏问题。

## 6. 风险、边界与改进建议

### 6.1 已知风险

#### 6.1.1 字段遗漏风险（历史问题）
**问题**: 生成的 `toJSON()` 会静默丢弃未知字段，曾导致以下字段未能到达 BigQuery：
- #11318
- #13924  
- #19448
- `coworker_type`

**缓解措施**: 现在在 `metadata.ts` 中使用 `EnvironmentMetadata` 类型进行编译时检查，确保新增字段必须先更新 Proto 定义。

#### 6.1.2 PII 数据泄露风险
**风险点**: `skill_name`, `plugin_name`, `marketplace_name` 等字段可能包含用户敏感信息。

**当前防护**:
- 这些字段通过 `_PROTO_*` 前缀标记（如 `_PROTO_skill_name`）
- 在 `sink.ts` 中通过 `stripProtoFields()` 从 Datadog 事件中移除
- 仅在 1P 事件日志中保留，且存储在受控访问的特权列中

#### 6.1.3 认证状态影响
**风险**: 401 认证错误会导致事件上报失败。

**缓解措施**: `FirstPartyEventLoggingExporter.sendBatchWithRetry()` 会在 401 错误时降级为无认证上报。

### 6.2 边界情况

#### 6.2.1 事件采样
- 通过 `tengu_event_sampling_config` 动态配置控制
- 采样率范围 0-1，0 表示全部丢弃，1 表示全部保留
- 采样事件会添加 `sample_rate` 元数据

#### 6.2.2 批量处理边界
- 默认批量大小: 200 事件 (`maxExportBatchSize`)
- 默认调度延迟: 5 秒 (`scheduledDelayMillis`)
- 最大队列大小: 8192

#### 6.2.3 失败重试机制
- 最大重试次数: 8 次（可配置）
- 退避策略: 二次退避 `base * attempts²`
- 最大退避延迟: 30 秒
- 失败事件持久化到磁盘: `~/.claude/telemetry/1p_failed_events.{sessionId}.{batchUuid}.json`

### 6.3 改进建议

#### 6.3.1 类型安全增强
```typescript
// 建议：为 additional_metadata 添加更严格的类型定义
// 当前是 string (Base64 JSON)，可考虑使用泛型约束
export interface ClaudeCodeInternalEvent<T extends EventMetadata = DefaultMetadata> {
  // ...
  additional_metadata?: T
}
```

#### 6.3.2 字段文档化
建议为每个字段添加 JSDoc 注释，说明：
- 字段用途
- 是否 PII
- 允许的值范围/格式
- 示例值

#### 6.3.3 版本兼容性
当前 `toJSON()` 静默丢弃未知字段，建议：
- 在开发/测试环境添加未知字段警告
- 或添加严格模式选项，遇到未知字段时抛出错误

#### 6.3.4 测试覆盖
建议添加：
- 序列化/反序列化 round-trip 测试
- 字段完整性测试（确保所有 Proto 字段都有对应 TS 字段）
- 边界值测试（空字符串、null、undefined 处理）

### 6.4 维护注意事项

1. **Proto 变更流程**: 修改字段必须先更新 monorepo 中的 `.proto` 文件，再运行 `bun run generate:proto`
2. **版本锁定**: `protoc-gen-ts_proto` 版本为 v2.6.1，升级需谨慎测试
3. **ESLint 禁用**: 文件顶部有 `/* eslint-disable */`，修改后需手动检查代码规范
