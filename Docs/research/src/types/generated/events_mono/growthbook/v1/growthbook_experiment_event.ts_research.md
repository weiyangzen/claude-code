## 场景与职责

`growthbook_experiment_event.ts` 是由 `protoc-gen-ts_proto` 自动生成的 TypeScript 模块，职责是为 Claude Code 的 1P（First-Party）事件日志系统提供 **GrowthBook 实验曝光事件** 的结构化类型定义与 JSON 序列化能力。

### 在整体系统中的位置

```
GrowthBook SDK (remoteEval)
    ↓
src/services/analytics/growthbook.ts  — 解析实验结果、缓存 feature 值
    ↓
logExposureForFeature() → logGrowthBookExperimentTo1P()
    ↓
src/services/analytics/firstPartyEventLogger.ts  — 构造 OTel LogRecord
    ↓
BatchLogRecordProcessor
    ↓
src/services/analytics/firstPartyEventLoggingExporter.ts
    ↓
GrowthbookExperimentEvent.toJSON({...})  ← 目标文件在此被调用
    ↓
POST /api/event_logging/batch
```

### 核心职责

1. **Schema 契约**：作为 `events_mono/growthbook/v1/growthbook_experiment_event.proto` 的 TypeScript 映射，定义实验曝光事件的所有字段。
2. **JSON 序列化**：提供 `toJSON()` 方法，将内存中的 TypeScript 对象转换为后端 BigQuery 可 ingestion 的 Protobuf JSON 格式。
3. **反序列化/构造**：提供 `fromJSON()`、`create()`、`fromPartial()` 用于测试、构造和部分更新。
4. **类型安全**：通过 `MessageFns<T>` 接口和 `Exact<DeepPartial<T>, I>` 约束，确保构造时不会出现未知字段。

## 功能点目的

### 1. 实验曝光追踪（Experiment Assignment Tracking）

Claude Code 使用 GrowthBook 进行 A/B 测试和 feature flag 管理。当用户首次访问某个带有实验来源的 feature 时，系统需要记录该用户被分配到了哪个实验变体（variation）。这对应 GrowthBook 文档中的 "exposure event" 概念，参考注释中的链接：https://docs.growthbook.io/guide/bigquery

### 2. 1P 事件统一格式

所有 1P 事件最终都通过 `/api/event_logging/batch` 发送。该端点要求事件包装为：

```typescript
{
  event_type: 'GrowthbookExperimentEvent',
  event_data: unknown  // Protobuf JSON
}
```

`GrowthbookExperimentEvent.toJSON()` 的输出就是 `event_data` 的值。

### 3. 字段设计意图

| 字段 | 类型 | 目的 |
|------|------|------|
| `event_id` | `string` | 去重标识，每次曝光生成一个 UUID |
| `timestamp` | `Date` | 曝光发生时间，映射到 GrowthBook 的 `timestamp` 列 |
| `experiment_id` | `string` | GrowthBook 实验 key |
| `variation_id` | `number` | 变体索引：`0=control`, `1+=variants` |
| `environment` | `string` | 环境标识（代码中硬编码为 `'production'`） |
| `user_attributes` | `string` | 分配时的用户属性 JSON 字符串 |
| `experiment_metadata` | `string` | 实验元数据 JSON 字符串（如关联的 `feature_id`） |
| `device_id` | `string` | 设备/用户标识（`getOrCreateUserID()`） |
| `auth` | `PublicApiAuth` | 账户/组织 UUID，用于后端关联 |
| `session_id` | `string` | 会话标识 |
| `anonymous_id` | `string` | 未认证用户的匿名标识 |
| `event_metadata_vars` | `string` | 由 `internal-tools-common event_logging` 库自动填充 |

注意：`user_attributes`、`experiment_metadata`、`event_metadata_vars` 三个字段在 proto 层面是 `string` 类型，实际存储的是 JSON 序列化后的内容。这种设计允许在不修改 proto 的情况下灵活添加嵌套字段，但代价是失去了编译期类型检查。

### 核心数据结构

#### `GrowthbookExperimentEvent` 接口

```typescript
export interface GrowthbookExperimentEvent {
  event_id?: string | undefined
  timestamp?: Date | undefined
  experiment_id?: string | undefined
  variation_id?: number | undefined
  environment?: string | undefined
  user_attributes?: string | undefined
  experiment_metadata?: string | undefined
```

所有字段均为可选（`optional` proto3 语义），使用 `| undefined` 而非 `?` 单独存在，以区分 "未设置" 和 "空字符串/0"。

#### `MessageFns<T>` 接口

```typescript
interface MessageFns<T> {
  fromJSON(object: any): T
  toJSON(message: T): unknown

```

该接口是 `ts_proto` 生成代码的标准契约。`GrowthbookExperimentEvent` 对象实现了此接口：

```typescript
export const GrowthbookExperimentEvent: MessageFns<GrowthbookExperimentEvent> = {
  fromJSON(object: any): GrowthbookExperimentEvent { ... },

  create<I extends Exact<DeepPartial<GrowthbookExperimentEvent>, I>>(base?: I): GrowthbookExperimentEvent { ... },
  fromPartial<I extends Exact<DeepPartial<GrowthbookExperimentEvent>, I>>(object: I): GrowthbookExperimentEvent { ... },
```

### 序列化行为（toJSON）

```typescript
toJSON(message: GrowthbookExperimentEvent): unknown {
  const obj: any = {}
  if (message.event_id !== undefined) {
    obj.event_id = message.event_id
  }
  if (message.timestamp !== undefined) {
    obj.timestamp = message.timestamp.toISOString()
  }
  if (message.variation_id !== undefined) {
    obj.variation_id = Math.round(message.variation_id)
  }
  // ... 其他字段类似
  if (message.auth !== undefined) {
    obj.auth = PublicApiAuth.toJSON(message.auth)
  }
  return obj
}
```

关键行为：
- **undefined 字段被省略**：不会输出 `null` 或默认值，保持 JSON 紧凑。
- **Date → ISO 8601 字符串**：`timestamp` 被转换为 `toISOString()` 格式。
- **number 取整**：`variation_id` 和 `PublicApiAuth.account_id` 都经过 `Math.round()`。
- **嵌套对象递归序列化**：`auth` 字段调用 `PublicApiAuth.toJSON()`。

### 反序列化行为（fromJSON）

```typescript
fromJSON(object: any): GrowthbookExperimentEvent {
  return {
    event_id: isSet(object.event_id) ? globalThis.String(object.event_id) : '',
    timestamp: isSet(object.timestamp) ? fromJsonTimestamp(object.timestamp) : undefined,
    variation_id: isSet(object.variation_id) ? globalThis.Number(object.variation_id) : 0,
    auth: isSet(object.auth) ? PublicApiAuth.fromJSON(object.auth) : undefined,
    // ...
  }
}
```

关键行为：
- 使用 `globalThis.String()` / `globalThis.Number()` 进行类型转换，避免环境差异。
- 时间戳支持三种输入：`Date` 实例、ISO 字符串、或 `{ seconds, nanos }` 对象（通过 `Timestamp.fromJSON`）。
- 未设置字段返回空字符串或 `undefined`（`timestamp` 和 `auth` 为 `undefined`，字符串字段为 `''`，`variation_id` 为 `0`）。

### 时间戳转换工具

```typescript
function fromTimestamp(t: Timestamp): Date {
  let millis = (t.seconds || 0) * 1_000
  millis += (t.nanos || 0) / 1_000_000
  return new globalThis.Date(millis)
}

function fromJsonTimestamp(o: any): Date {
  if (o instanceof globalThis.Date) {
    return o
  } else if (typeof o === 'string') {
    return new globalThis.Date(o)
  } else {
    return fromTimestamp(Timestamp.fromJSON(o))
  }
}
```

这是标准的 Protobuf `google.protobuf.Timestamp` JSON 映射实现。

### 类型工具

```typescript
type Builtin = Date | Function | Uint8Array | string | number | boolean | undefined

type DeepPartial<T> = T extends Builtin
  ? T
  : T extends globalThis.Array<infer U>
    ? globalThis.Array<DeepPartial<U>>
    : T extends ReadonlyArray<infer U>
      ? ReadonlyArray<DeepPartial<U>>
      : T extends {}
        ? { [K in keyof T]?: DeepPartial<T[K]> }
        : Partial<T>

type Exact<P, I extends P> = P extends Builtin
  ? P
  : P & { [K in keyof P]: Exact<P[K], I[K]> } & {
      [K in Exclude<keyof I, KeysOfUnion<P>>]: never
    }
```

`Exact` 类型确保 `create` 和 `fromPartial` 的输入不能包含目标接口中不存在的字段，提供编译期防御。

1. **GrowthBook SDK** (`@growthbook/growthbook`)

## 风险、边界与改进建议

### 风险点

#### 1. 生成代码不可编辑，但修改链路长
- **风险**：开发者可能误以为可以直接修改 `.ts` 文件来添加字段。
- **现状**：proto 源文件位于 monorepo 其他位置（`go/cc-logging`），需要通过 `bun run generate:proto` 重新生成。
- **建议**：在文件头部注释已足够明确（`DO NOT EDIT`），但在团队文档中应强调 proto-first 的变更流程。

#### 2. JSON 字符串字段缺乏编译期类型安全
- **风险**：`user_attributes`、`experiment_metadata`、`event_metadata_vars` 是 `string` 类型，但实际要求是合法 JSON。如果上游调用方传入未序列化的对象或非 JSON 字符串，后端解析会失败。
- **现状**：`firstPartyEventLogger.ts` 中使用 `jsonStringify()` 进行序列化，但这不是类型系统强制的。
- **建议**：在 `firstPartyEventLogger.ts` 的 `GrowthBookExperimentData` 类型中，将 `userAttributes` 和 `experimentMetadata` 从 `Record<string, unknown>` 改为更严格的类型，并确保在边界处统一调用 `jsonStringify`。

#### 3. `event_metadata_vars` 字段的填充责任不清
- **风险**：注释说明该字段 "automatically populated by internal-tools-common event_logging library"，但客户端代码中没有任何地方设置它。如果后端期望该字段存在，而客户端未发送，可能导致数据不完整。
- **现状**：`firstPartyEventLoggingExporter.ts` 的 `transformLogsToEvents` 中没有为 `GrowthbookExperimentEvent` 设置 `event_metadata_vars`。
- **建议**：明确该字段是否应由服务端在接收后填充。如果确实需要客户端填充，应在 `logGrowthBookExperimentTo1P()` 或 Exporter 中添加相应逻辑。

#### 4. 生成代码重复导致包体积膨胀
- **风险**：`DeepPartial`、`Exact`、`isSet`、`fromTimestamp`、`fromJsonTimestamp`、`MessageFns` 等工具类型和函数在每个 `ts_proto` 生成文件中都有一份完全相同的副本。当前仓库已有 4 个生成文件，未来可能更多。
- **现状**：没有共享的生成工具库。
- **建议**：配置 `ts_proto` 使用 `--importSuffix=.js` 和外部辅助库选项（如 `ts_proto` 的 `outputServices=...` 不直接相关，但可以通过 `esModuleInterop` 或自定义生成模板减少重复）。

#### 5. `auth` 字段的 `account_id` 永远不会被客户端填充
- **风险**：`PublicApiAuth` 接口包含 `account_id?: number`，但客户端代码（`firstPartyEventLogger.ts` 和 `metadata.ts`）只填充 `account_uuid` 和 `organization_uuid`。`account_id` 作为数字 ID 在 modern UUID-based 系统中已废弃，但 proto 中仍保留该字段。
- **建议**：在 proto 层面将 `account_id` 标记为 `reserved` 或移除，避免未来开发者误用。

### 边界情况

1. **空对象序列化**
   - `GrowthbookExperimentEvent.toJSON({})` 返回 `{}`，所有 undefined 字段被省略。API 接收后可能因缺少必填字段而拒绝，但这属于调用方责任。

2. **部分字段缺失**
   - `fromPartial` 对缺失字段使用默认值：`''`（字符串）、`0`（number）、`undefined`（Date/嵌套对象）。这与 proto3 的默认语义一致。

3. **timestamp 输入兼容性**
   - `fromJSON` 支持 `Date` 实例、ISO 字符串、`{ seconds, nanos }` 对象三种格式，容错性较强。

4. **GrowthBook 未初始化或禁用**
   - 如果 `is1PEventLoggingEnabled()` 返回 false（如测试环境、第三方云提供商、用户 opt-out），则 `GrowthbookExperimentEvent` 永远不会被构造和序列化。

### 改进建议

1. **引入运行时 JSON 验证**
   ```typescript
   // 在 firstPartyEventLogger.ts 的 logGrowthBookExperimentTo1P 中
   function safeJsonStringify(value: unknown): string {
     try {
       return jsonStringify(value)
     } catch {
       return '{}'
     }
   }
   ```
   已在部分代码中使用，但可统一为工具函数。

2. **ts_proto 生成配置优化**
   - 调研 `ts_proto` 的 `outputJsonMethods=false` 或 `outputPartialMethods=false` 是否可关闭未使用的方法（如 `fromJSON` 在本文件中几乎只用于测试）。
   - 使用 `outputServices=grpc-js` 不适用，但可考虑 `--ts_proto_opt=useOptionals=all` 以简化可选字段语义。

3. **添加单元测试覆盖序列化边界**
   - 当前仓库中没有发现针对 `GrowthbookExperimentEvent.toJSON` 的单元测试。
   - 建议测试：
     - 所有字段齐全的完整序列化
     - `undefined` 字段的省略行为
     - `timestamp` 的 ISO 格式输出
     - `Math.round` 对 `variation_id` 的行为
     - 嵌套 `auth` 对象的递归序列化

4. **统一生成工具库**
   - 将 `DeepPartial`、`Exact`、`isSet`、`fromJsonTimestamp` 提取到 `src/types/generated/proto-helpers.ts`，让各生成文件 `import` 而非内联复制。

5. **文档化字段映射关系**
   - 在 `firstPartyEventLogger.ts` 的 `logGrowthBookExperimentTo1P` 函数注释中，显式列出 `GrowthBookExperimentData` 到 `GrowthbookExperimentEvent` 字段的映射表，降低维护成本。
