# cron.ts 深度研究文档

## 场景与职责

`cron.ts` 是 Claude Code 的 **Cron 表达式解析与调度核心模块**，提供轻量级的定时任务调度能力。它是整个定时任务系统的基础层，负责将人类可读的 cron 表达式转换为机器可执行的时间计算。

### 核心职责

1. **Cron 表达式解析**：将 5 字段 cron 字符串解析为结构化的字段数组
2. **下次执行计算**：基于当前时间计算下一次应该触发的时间点
3. **人类可读转换**：将 cron 表达式转换为友好的自然语言描述

### 使用场景

- **定时任务创建**：用户通过 `CronCreateTool` 创建定时任务时验证和解析 cron 表达式
- **调度器核心**：`cronScheduler.ts` 使用本模块计算任务下次触发时间
- **任务列表展示**：`CronListTool` 使用 `cronToHuman` 展示友好的调度描述
- **Daemon 模式**：SDK/headless 模式下的定时任务调度

## 功能点目的

### 1. Cron 表达式解析 (`parseCronExpression`)

**目的**：将标准 5 字段 cron 表达式（`分 时 日 月 周`）解析为可计算的数据结构。

**支持的语法**：
- **通配符**：`*`（匹配所有值）
- **具体值**：`5`, `14`（匹配特定值）
- **步长**：`*/5`, `0-30/5`（每隔 N 个单位）
- **范围**：`1-5`, `9-17`（匹配范围内的值）
- **列表**：`1,3,5`, `0,30`（匹配多个特定值）
- **周日别名**：`7` 被视为 `0`（周日）

**字段范围**：
| 字段 | 范围 | 说明 |
|------|------|------|
| minute | 0-59 | 分钟 |
| hour | 0-23 | 小时 |
| dayOfMonth | 1-31 | 日期 |
| month | 1-12 | 月份 |
| dayOfWeek | 0-6 | 星期（0=周日）|

### 2. 下次执行计算 (`computeNextCronRun`)

**目的**：计算严格晚于给定时间的下一个匹配时间点。

**算法特点**：
- **分钟级精度**：从 `from + 1 分钟` 开始搜索
- **366 天上限**：防止无限循环，无效 cron 返回 `null`
- **DST 处理**：正确处理夏令时切换（跳过不存在的时钟，重复时钟只触发一次）
- **OR 语义**：当 `dayOfMonth` 和 `dayOfWeek` 都受限时，满足任一条件即匹配

**优化策略**：
- 月份不匹配：跳到下月 1 日 0:00
- 日期不匹配：跳到下日 0:00
- 小时不匹配：跳到下一小时 0 分
- 分钟不匹配：分钟 +1

### 3. 人类可读转换 (`cronToHuman`)

**目的**：将 cron 表达式转换为自然语言描述，方便用户理解。

**支持的转换模式**：

| Cron 模式 | 输出示例 |
|-----------|----------|
| `*/5 * * * *` | "Every 5 minutes" |
| `0 * * * *` | "Every hour" |
| `0 */3 * * *` | "Every 3 hours" |
| `30 9 * * *` | "Every day at 9:30 AM" |
| `0 10 * * 1` | "Every Monday at 10:00 AM" |
| `0 9 * * 1-5` | "Weekdays at 9:00 AM" |

**UTC 支持**：`{ utc: true }` 选项用于 CCR 远程触发器，将 UTC 时间转换为本地时间显示。

## 具体技术实现

### 核心数据结构

```typescript
// 解析后的 cron 字段
type CronFields = {
  minute: number[]      // 匹配的所有分钟值（已排序）
  hour: number[]        // 匹配的所有小时值
  dayOfMonth: number[]  // 匹配的所有日期值
  month: number[]       // 匹配的所有月份值
  dayOfWeek: number[]   // 匹配的所有星期值
}

// 字段范围定义
 type FieldRange = { min: number; max: number }
const FIELD_RANGES: FieldRange[] = [
  { min: 0, max: 59 },  // minute
  { min: 0, max: 23 },  // hour
  { min: 1, max: 31 },  // dayOfMonth
  { min: 1, max: 12 },  // month
  { min: 0, max: 6 },   // dayOfWeek (0=Sunday; 7 accepted as alias)
]
```

### 字段展开算法 (`expandField`)

```
输入: field (string), range (FieldRange)
输出: number[] | null

1. 按逗号分割字段 → parts[]
2. 对每个 part:
   a. 匹配 */N 或 * → 生成步长序列
   b. 匹配 N-M 或 N-M/S → 生成范围序列
   c. 匹配 N → 单值
   d. 都不匹配 → 返回 null (无效)
3. 合并所有值到 Set（去重）
4. 排序返回数组
```

### 下次执行搜索算法

```
输入: fields (CronFields), from (Date)
输出: Date | null

1. 创建 Set 加速查找
2. 判断 dayOfMonth 和 dayOfWeek 是否为通配
3. 从 from + 1 分钟开始
4. 最多迭代 366 * 24 * 60 次:
   a. 检查月份 → 不匹配则跳到下月
   b. 检查日期+星期 → 不匹配则跳到下日
   c. 检查小时 → 不匹配则跳到下一小时
   d. 检查分钟 → 不匹配则分钟+1
   e. 全部匹配 → 返回当前时间
5. 超过上限 → 返回 null
```

### 日期匹配逻辑

```typescript
// 标准 cron 语义：当两者都受限时，OR 逻辑
const dayMatches =
  domWild && dowWild ? true           // 都是通配 → 总是匹配
  : domWild ? dowSet.has(dow)         // 只有星期受限
  : dowWild ? domSet.has(dom)         // 只有日期受限
  : domSet.has(dom) || dowSet.has(dow) // 两者都受限 → OR
```

### API 设计原则

1. **纯函数**：所有导出函数都是纯函数，无副作用
2. **不可变性**：不修改输入参数
3. **容错性**：无效输入返回 `null` 而非抛出异常
4. **时区处理**：所有时间使用本地时区（调用方负责 UTC 转换）

## 风险、边界与改进建议

### 已知风险

1. **DST 边界情况**
   - 春令时切换时，2:00-3:00 的时间段不存在
   - 秋令时切换时，1:00-2:00 的时间段重复
   - 当前实现与 vixie-cron 行为一致，但可能不符合所有用户预期

2. **性能上限**
   - 366 天的搜索上限意味着极罕见的 cron（如 `0 0 29 2 *` 闰年）可能找不到匹配
   - 分钟级迭代在极端情况下可能较慢（但 366*24*60 = 527k 次迭代在现代 CPU 上很快）

3. **语法限制**
   - 不支持 `L`（最后一天）、`W`（最近工作日）、`?`（无特定值）等扩展语法
   - 不支持月份和星期的名称别名（如 `JAN`、`MON`）

### 边界情况

| 场景 | 处理 |
|------|------|
| 空字符串 | 返回 `null` |
| 字段数 ≠ 5 | 返回 `null` |
| 无效数值（如 70 分钟） | 返回 `null` |
| 范围反转（如 5-1） | 返回 `null` |
| 步长 < 1 | 返回 `null` |
| 无匹配时间（366 天内） | 返回 `null` |
| 周日 = 7 | 自动转换为 0 |

### 改进建议

1. **功能扩展**
   - 添加对 `L`、`W`、`?` 等特殊字符的支持
   - 添加月份和星期名称别名支持
   - 添加时区参数支持（而非仅本地时间）

2. **性能优化**
   - 对于简单模式（如每小时、每天）使用直接计算而非迭代
   - 添加缓存机制避免重复计算相同 cron 表达式

3. **错误处理**
   - 提供更详细的错误信息（哪个字段无效、为什么无效）
   - 考虑返回 `Result<T, E>` 类型而非 `T | null`

4. **测试覆盖**
   - 添加 DST 切换的边界测试
   - 添加所有语法变体的组合测试
   - 添加性能基准测试

5. **文档完善**
   - 添加 cron 语法速查表到用户文档
   - 记录 DST 处理行为的详细说明
