# pasteStore.ts 研究文档

## 场景与职责

本模块提供粘贴内容的持久化存储功能。核心职责包括：

1. **粘贴内容存储**：将用户粘贴的文本内容保存到磁盘
2. **内容寻址**：使用 SHA-256 哈希作为文件名，实现内容寻址
3. **内容检索**：通过哈希值检索之前存储的粘贴内容
4. **过期清理**：支持按时间清理旧的粘贴文件

该模块是粘贴处理系统的基础设施，用于跨会话保留粘贴历史，支持粘贴内容的引用和恢复。

## 功能点目的

### 1. `hashPastedText()` - 粘贴内容哈希
- **目的**：为粘贴内容生成唯一标识（SHA-256 哈希）
- **输出**：16 字符十六进制字符串（哈希前 8 字节）
- **特点**：同步函数，调用方可立即获得哈希而无需等待异步存储

### 2. `storePastedText()` - 粘贴内容存储
- **目的**：将粘贴文本异步写入磁盘
- **存储位置**：`~/.claude/paste-cache/${hash}.txt`
- **文件权限**：`0o600`（仅所有者可读写）
- **特点**：内容寻址，相同内容覆盖安全

### 3. `retrievePastedText()` - 粘贴内容检索
- **目的**：通过哈希值检索之前存储的粘贴内容
- **返回值**：内容字符串或 null（未找到/错误）
- **错误处理**：ENOENT 视为正常未找到，其他错误记录日志

### 4. `cleanupOldPastes()` - 过期粘贴清理
- **目的**：清理指定日期之前的旧粘贴文件
- **策略**：基于文件 mtime 的时间清理
- **容错**：单个文件错误不影响整体清理

## 具体技术实现

### 关键流程

#### 粘贴存储流程

```
用户粘贴内容
    ↓
hashPastedText(content) → 16字符哈希
    ↓
storePastedText(hash, content)
    ↓
确保目录存在（mkdir recursive）
    ↓
写入文件（mode 0o600）
    ↓
记录调试日志
```

#### 粘贴检索流程

```
需要检索粘贴内容
    ↓
retrievePastedText(hash)
    ↓
读取文件
    ↓
成功 → 返回内容
失败 ENOENT → 返回 null
失败 其他 → 记录日志，返回 null
```

#### 过期清理流程

```
cleanupOldPastes(cutoffDate)
    ↓
读取 paste-cache 目录
    ↓
过滤 .txt 文件
    ↓
逐个检查 mtime
    ↓
mtime < cutoffDate?
    是 → unlink 删除
    否 → 保留
    ↓
记录删除日志
```

### 数据结构

```typescript
// 常量
const PASTE_STORE_DIR = 'paste-cache'

// 文件路径格式
~/.claude/paste-cache/${hash}.txt

// 哈希格式
SHA-256(content).digest('hex').slice(0, 16)
// 示例: "a1b2c3d4e5f67890"
```

### 安全设计

| 措施 | 实现 |
|------|------|
| 文件权限 | `mode: 0o600`（仅所有者可读写） |
| 路径安全 | 哈希值作为文件名，无路径遍历风险 |
| 内容寻址 | 相同哈希 = 相同内容，防篡改 |
| 目录隔离 | 专用 `paste-cache` 子目录 |

## 风险、边界与改进建议

### 已知风险

1. **哈希碰撞**
   - 风险：不同内容产生相同 16 字符哈希前缀
   - 概率：SHA-256 前 64 位，碰撞概率极低
   - 影响：内容被错误覆盖
   - 缓解：使用完整哈希或增加长度

2. **磁盘空间**
   - 风险：大量粘贴内容占用磁盘空间
   - 现状：依赖外部 `cleanupOldPastes` 调用
   - 建议：添加自动过期机制

3. **并发写入**
   - 风险：相同内容同时写入
   - 缓解：内容寻址，覆盖安全
   - 潜在问题：文件系统竞争条件

4. **权限问题**
   - 风险：目录权限导致写入失败
   - 处理：静默失败（仅记录日志）
   - 影响：粘贴内容无法持久化

### 边界情况

| 场景 | 行为 |
|------|------|
| 空内容 | 正常哈希和存储 |
| 超大内容 | 无限制，可能占用大量磁盘空间 |
| 特殊字符 | 哈希后无特殊处理问题 |
| 二进制内容 | 模块设计为文本，二进制可能损坏 |
| 目录不存在 | `mkdir({ recursive: true })` 自动创建 |
| 文件已存在 | 覆盖写入（内容寻址安全） |
| 读取权限不足 | 返回 null，记录日志 |
| 清理时目录不存在 | 静默返回，无错误 |

### 改进建议

1. **哈希长度配置**
   - 当前：固定 16 字符
   - 建议：可配置长度，平衡碰撞概率和文件名长度

2. **自动过期**
   - 当前：依赖外部调用清理
   - 建议：
     - 存储时记录时间戳元数据
     - 读取时检查过期
     - 定期后台清理

3. **大小限制**
   - 当前：无大小限制
   - 建议：
     - 添加 `MAX_PASTE_SIZE` 常量
     - 超大内容拒绝或截断存储

4. **压缩存储**
   - 建议：对重复内容使用引用计数
   - 或：使用 gzip 压缩存储

5. **元数据增强**
   - 当前：仅存储内容
   - 建议：
     - 存储时间戳
     - 存储来源（IDE、终端等）
     - 存储内容类型

6. **加密存储**
   - 当前：明文存储
   - 建议：敏感内容加密存储
   - 考虑：使用系统密钥链

7. **配额管理**
   - 建议：
     - 设置总存储配额
     - LRU 淘汰旧内容
     - 配额使用统计

8. **跨设备同步**
   - 建议：
     - 云同步支持
     - 设备间粘贴共享

9. **搜索功能**
   - 建议：
     - 内容索引
     - 全文搜索
     - 标签支持

10. **遥测集成**
    - 建议：
      - 记录存储/检索频率
      - 记录存储大小分布
      - 记录命中率
