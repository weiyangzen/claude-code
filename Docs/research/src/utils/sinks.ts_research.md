# sinks.ts 深度研究

## 场景与职责

`sinks.ts` 是一个**叶节点模块**，负责初始化和附加错误日志和分析接收器（sinks）。它从 `setup.ts` 中分离出来，避免循环依赖。

**核心职责：**
1. 初始化错误日志接收器
2. 初始化分析接收器
3. 排空初始化前队列中的事件

**设计背景：**
- 避免 `setup.ts → commands → bridge → setup` 的导入循环
- 作为入口点（子命令、守护进程、bridge）直接调用的独立模块

---

## 功能点目的

### 接收器初始化
```typescript
export function initSinks(): void
```

**操作：**
1. `initializeErrorLogSink()` - 初始化错误日志接收器
2. `initializeAnalyticsSink()` - 初始化分析接收器

**特点：**
- 两个初始化都是幂等的
- 自动排空初始化前队列的事件

## 风险、边界与改进建议

### 已知风险

1. **初始化顺序**
   - 必须在其他模块记录事件前调用
   - 过早调用可能导致接收器未就绪

2. **幂等性依赖**
   - 依赖底层接收器的幂等实现
   - 重复调用不应产生副作用

### 边界情况

| 场景 | 处理 |
|------|------|
| 重复调用 | 幂等，无额外副作用 |
| 部分失败 | 依赖底层接收器的错误处理 |
| 事件队列排空失败 | 依赖底层接收器的重试机制 |

### 改进建议

1. **健康检查**
   - 添加接收器健康状态查询
   - 提供初始化失败诊断

2. **延迟初始化**
   - 支持按需初始化特定接收器
   - 减少启动时间

3. **配置支持**
   - 允许通过参数配置接收器行为
   - 支持动态启用/禁用

4. **监控集成**
   - 添加接收器性能指标
   - 记录队列深度和排空时间

5. **文档增强**
   - 明确调用时序要求
   - 提供故障排查指南
