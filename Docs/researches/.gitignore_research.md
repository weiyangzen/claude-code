# .gitignore 研究

## 场景与职责
`.gitignore` 位于仓库根目录，是 Git 的“未跟踪文件过滤入口”。当前文件仅包含一条规则：忽略 `.DS_Store`。其职责集中在：

- 屏蔽 macOS Finder 自动生成的元数据文件，减少 `git status` 噪音。
- 避免无业务价值的系统文件进入提交历史。

在本仓库研究流程里，`.gitignore` 还影响开发者的日常提交流程（`git add -A` 时更干净），但不会直接驱动 `.ops` 脚本逻辑。

## 功能点目的
当前文件内容：

```gitignore
.DS_Store
```

功能点目的：

1. 忽略任意层级的 `.DS_Store`
- 该模式未带路径前缀，能匹配仓库根目录及子目录中的同名文件。
- 目的：统一清除 macOS 桌面环境噪音文件。

## 具体技术实现（关键流程/数据结构/协议/命令）
Git 的忽略机制在当前文件中的实现要点：

1. 匹配阶段
- Git 在扫描未跟踪文件时读取 `.gitignore` 规则并进行路径匹配。
- 命中后文件不再出现在默认 `git status` 的未跟踪列表。

2. 作用边界
- `.gitignore` 仅影响“未被追踪”的文件。
- 若文件已被追踪，新增忽略规则不会自动停止跟踪（需 `git rm --cached` 类操作配合）。

仓库内实测命令：

```bash
git check-ignore -v .DS_Store Docs/.DS_Store plugins/.DS_Store
```

实测结果显示三条路径均命中 `.gitignore:1:.DS_Store`，说明根规则可覆盖子目录。

补充边界验证（与脚本关系）：

- `.ops/generate_research_blueprint_checklist.sh:27-42` 使用 `find` 扫描文件系统生成 checklist，不读取 `.gitignore`。
- 因此 `.gitignore` 并不会阻止该脚本把“真实存在于磁盘”的文件纳入蓝图（只是在日常 Git 提交里隐藏它们）。

## 关键代码路径与文件引用
- `.gitignore:1`：唯一规则定义。
- `.ops/generate_research_blueprint_checklist.sh:27-42`：文件扫描逻辑（基于 `find`，非 Git ignore 语义）。
- `.ops/generate_daily_research_todo.sh:15-18`：从 checklist 汇总 pending/done，间接受上一步扫描结果影响。
- `CHANGELOG.md:1104`：`respectGitignore` 配置被引入（产品层面对 ignore 语义的支持演进）。
- `CHANGELOG.md:648`：修复 LSP 返回 gitignored 文件结果的问题，体现 `.gitignore` 在工具链中的边界管理价值。

## 依赖与外部交互
- 直接依赖：Git ignore 规则解析。
- 外部交互：
  - macOS Finder（`.DS_Store` 生产者）。
  - 开发者本地 Git 工作流（`status/add/clean` 等命令的输出体验）。
- 间接关联：
  - 仓库中的插件/文档多处提到“.env 应写入 .gitignore”，说明 `.gitignore` 也是安全治理实践的一部分（防止敏感配置误入库）。

## 风险、边界与改进建议
风险与边界：

1. 根规则过于精简
- 当前仅忽略 `.DS_Store`，对其他常见噪音（如 `Thumbs.db`、编辑器临时文件）无覆盖。

2. 与自动化扫描边界不一致
- 研究蓝图脚本不尊重 `.gitignore`，如果工作区出现忽略文件，仍可能被扫描到研究清单中，造成流程噪音。

3. 运行时产物可能持续污染工作区
- 当前仓库出现 `.cron/research_guard.log` 的跟踪修改，表明部分运行时文件未通过 ignore 策略与产物策略解耦。

改进建议：

1. 按仓库实际产物补充忽略项
- 例如跨平台系统文件与编辑器临时文件（在不影响示例教学前提下精简噪音）。

2. 为研究脚本增加“可选 respect-gitignore 模式”
- 在 `.ops/generate_research_blueprint_checklist.sh` 提供开关，允许按 Git 视图而非纯文件系统视图生成蓝图。

3. 区分“应跟踪运行日志”与“仅本地运行痕迹”
- 若 `.cron/*` 主要是本地运行态，建议转为忽略或改为输出到 Git 之外目录。
