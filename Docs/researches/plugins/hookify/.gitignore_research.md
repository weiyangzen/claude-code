# FILE `plugins/hookify/.gitignore` 研究文档

## 场景与职责

`plugins/hookify/.gitignore` 是 Hookify 插件目录级的 Git 忽略策略文件，职责不是运行时逻辑，而是约束“哪些本地/临时产物不应被版本控制追踪”。

在 hookify 这个插件里，它主要服务三个场景：
- Python 开发与执行场景：屏蔽 `__pycache__/`、`*.py[cod]`、`*.so` 等解释器/构建副产物，避免提交噪音（`plugins/hookify/.gitignore:1-6`）。
- 本地调试场景：屏蔽虚拟环境目录、IDE 临时文件、系统文件，减少跨系统协作冲突（`plugins/hookify/.gitignore:8-21`）。
- 规则本地化场景：屏蔽插件目录下 `.claude/*.local.md|json`，避免把个人本地规则误提交（`plugins/hookify/.gitignore:28-30`）。

它与运行时执行链（`hooks/hooks.json -> hooks/*.py -> core/*`）没有直接调用关系，但与规则文件交付流程有明确边界：
- `/hookify` 命令明确要求把规则写到“项目根 `.claude/`”而不是“插件目录 `.claude/`”（`plugins/hookify/commands/hookify.md:128-138,206-207`）。
- 因此本文件更多是“插件自身开发防护”，不是“项目规则目录防护”的唯一手段。

## 功能点目的

按分组说明每组规则意图：

1. `# Python` 分组（`plugins/hookify/.gitignore:1-6`）
- 目的：忽略 Python 解释执行与扩展产物，避免无意义二进制/缓存进入仓库。
- 关键条目：`__pycache__/`、`*.py[cod]`、`*$py.class`、`*.so`、`.Python`。

2. `# Virtual environments` 分组（`plugins/hookify/.gitignore:8-11`）
- 目的：忽略本地虚拟环境，避免团队成员各自环境被提交。
- 关键条目：`venv/`、`env/`、`ENV/`。

3. `# IDE` 分组（`plugins/hookify/.gitignore:13-17`）
- 目的：忽略编辑器工程配置及交换文件，降低编辑器差异导致的脏改动。
- 关键条目：`.vscode/`、`.idea/`、`*.swp`、`*.swo`。

4. `# OS` 分组（`plugins/hookify/.gitignore:19-21`）
- 目的：忽略系统自动生成文件（macOS/Windows）。

5. `# Testing` 分组（`plugins/hookify/.gitignore:23-26`）
- 目的：忽略测试缓存和覆盖率产物，避免调试结果污染仓库。

6. `# Local configuration` 分组（`plugins/hookify/.gitignore:28-30`）
- 目的：避免插件目录下 `.claude/*.local.*` 被提交。
- 该规则与 README“规则无需重启即时生效”配套（`plugins/hookify/README.md:28-29,305-310`），鼓励本地快速迭代时不污染版本库。

## 具体技术实现（关键流程/数据结构/协议/命令）

### 1) 技术实现本质

本文件由 Git 的 ignore 机制解释，不涉及 Python 运行。
- 触发方：`git status`、`git add`、`git clean` 等命令。
- 语法：glob 风格模式，目录后缀 `/` 表示目录匹配，`*` 表示通配。

### 2) 在 hookify 生命周期中的作用点

1. 开发者运行 Hook 脚本（`plugins/hookify/hooks/*.py`）与核心逻辑（`plugins/hookify/core/*.py`）时会生成缓存。
2. `.gitignore` 防止这些缓存被当作“待提交改动”。
3. 用户依据 README 或命令文档创建本地规则时，若误在插件目录建立 `.claude/*.local.md`，可被该文件屏蔽提交。

### 3) 与当前仓库状态的交叉验证

当前 `plugins/hookify` 下存在已跟踪的 `__pycache__/*.pyc` 文件（如 `plugins/hookify/core/__pycache__/...`、`plugins/hookify/hooks/__pycache__/...`），说明：
- `.gitignore` 仅影响“未跟踪文件”，不会自动移除“已跟踪文件”；
- 这会造成规则存在但历史遗留缓存仍在仓库中的现象。

### 4) 与命令/文档协议的关系

- `/hookify` 工作流通过命令文档将规则目标目录固定为“当前项目 `.claude/`”（`plugins/hookify/commands/hookify.md:128-137`）。
- README 也把规则文件示例写为项目 `.claude/hookify.*.local.md`（`plugins/hookify/README.md:75,99,306`）。
- 因此本 `.gitignore` 的 `.claude/*.local.*` 实际更像“插件仓库自保兜底”。

## 风险、边界与改进建议

1. 风险：已跟踪缓存文件不会被该文件清理。
- 现状：仓库已存在 `__pycache__/*.pyc` 跟踪项。
- 建议：执行一次性去追踪（如 `git rm --cached` 对应缓存路径）并提交，后续交由 `.gitignore` 托管。

2. 风险：虚拟环境命名覆盖不全。
- 现状：有 `venv/env/ENV`，但常见 `.venv/` 未覆盖。
- 建议：补充 `.venv/`，减少漏网。

3. 风险：Python 工具缓存未覆盖。
- 现状：未忽略 `.mypy_cache/`、`.ruff_cache/`、`.hypothesis/`、`.tox/`、`.nox/`、`.coverage.*`。
- 建议：按团队实际工具链补齐，避免 CI/本地辅助缓存被误纳入。

4. 边界：该文件只作用于插件目录，不自动覆盖“项目根 `.claude/`”。
- 建议：在项目模板或 README 中明确提示用户在项目根 `.gitignore` 也添加 `.claude/*.local.md` 与 `.claude/*.local.json`，确保本地规则不外泄。

5. 改进：与文档保持单一事实源。
- 建议在 `README.md` 增加“Git ignore 建议段落”，避免用户误以为插件目录 `.gitignore` 可以保护所有项目目录。
